Предложить функцию ​

Расскажите, чего не хватает в работе. Форма ниже соберёт описание и откроет новую задачу на GitHub с уже заполненным текстом — останется нажать «Submit new issue». Ничего не отправляется автоматически, черновик сохраняется в этом браузере.

Форма ничего не отправляет на сервер: она собирает текст и открывает новую задачу на GitHub с уже заполненным описанием. Аккаунт GitHub нужен только для отправки.

Открыть задачу на GitHub

Заполните название (от 3 символов) и описание проблемы (от 10 символов).

Предпочитаете обсуждение вместо задачи? Написать в Discussions.

Что помогает предложению ​

  • Опишите задачу, а не решение. «Нужно быстро проверить, что контур не выходит за границу района» полезнее, чем «добавьте кнопку X».
  • Дайте пример. Ссылка на объект, скриншот, кусочек файла — если можно показать без закрытых данных.
  • Скажите, как часто это нужно. Раз в день или раз в год — от этого зависит приоритет.
  • Укажите раздел. «Редактор», «Модерация» или «Стиль» — так предложение попадёт к нужной части интерфейса.

Что происходит дальше ​

  1. Задача появляется в Issues с меткой enhancement.
  2. Её читают, уточняют детали в комментариях, при необходимости добавляют метки приоритета.
  3. Реализованное попадает в раздел «Версии» и в справку.

Сроков не обещаем: проект развивается силами автора и участников. Небольшие улучшения обычно доезжают быстрее крупных.

Если GitHub недоступен ​

  • Напишите в обсуждение идей — там можно предложить идею без оформления задачи.
  • Кнопка «Скопировать текст» в форме положит готовое описание в буфер обмена: его можно отправить любым удобным способом.

Чего лучше не предлагать ​

  • Обход лимитов редактора. Лимит вершин и правила модерации — часть платформы, расширение их не обходит.
  • Автоматическую правку чужих объектов. Инструменты расширения помогают человеку, а не заменяют модерацию.
  • Сбор данных о пользователях. Расширение не собирает статистику и не отправляет геоданные на сторонние серверы.
